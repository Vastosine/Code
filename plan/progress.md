## 复杂度估算标尺（本机实测，g++ -O2，2026-10-31）

「大概会超时」必须是一个数。以下是本机 `stress/sigma_bench/` 量的硬数字，用来把「感觉」换成「估算」。

| 操作 | 规模 | 实测 | 折算 |
|---|---|---|---|
| 约数筛 `for d: for m=d..N step d: sig[m]+=d` | N=1e7，**1.63e8 次** | **1280 ms** | 7.9 ns/次（步长变大后 cache miss 主导） |
| 线性筛 σ（积性函数） | N=1e7，~2e7 次内层 | **137 ms** | 7 ns/次 |
| 反查表 `ans[sig[n]]=n` | 1e7 次，跨 40 MB 数组随机写 | **106 ms** | 10.6 ns/次 |
| 1e4 次查询随机读 40 MB 数组 | 1e4 | **0.23 ms** | 22 ns/次 |

**标尺**：跨 40 MB 数组的**随机访问 ≈ 10 ns/次**（DRAM 延迟）；**顺序加法 ≈ 1–3 ns/次**。
所以 **1e8 次随机访问 ≈ 1 s，1e8 次顺序加法 ≈ 0.1–0.3 s**。估复杂度时先问「是顺序还是要跳」。

**整数除法很贵**：线性筛里把 `i > n/p` 换成 `1LL*i*p > n`，N=1e7 从 **151 ms → 74 ms**（2×）。除法约 20–40 周期、乘法 1 周期，9.3e6 次差 80 ms。「用除法防溢出」是错的习惯——**用 64 位乘法防溢出，别用除法**。

| 线性筛 N=1e7 | 除法 `i > n/p` | 64 位乘法 `1LL*i*p > n` |
|---|---|---|
| `vector<int>` 标志 | 151 ms | 74 ms |
| `vector<char>` 标志 | 145 ms | **63 ms** |

> 同一天的教训：1512G 一开始就被「预处理会超时」否掉了，但那个判断没量化。实测约数筛 1280 ms / TL 2000 ms——**数量级上他猜对了，可结论应该是「换更便宜的筛法」，不是「放弃预处理」**。同一想法两种实现差 **9.3 倍**（1280 → 137 ms），两种实现的 σ 在 1e7 个值上逐一对拍完全一致。

## 数位 DP 到底是什么（2026-11-08 澄清）

**不是「DP 套了数字」。** 是：

> **把「≤ X」这个全序约束，编码成一个有限状态（`tight ∈ {0,1}`），从而把「所有不超过 X 的数」变成一张表上的路径计数。**

两条支柱：

1. $f(a,b) = f(0,b) - f(0,a) + g(a)$ —— 把区间变成两个「前缀」相减（避免 2000 位大数减一）
2. `nt = tight && (dig == X[pos])` —— 把上界从**控制流**变成**状态**

**必须用状态而不是控制流的判据**：当有第二个能「提前终止」的约束时（628D 的 `d` 奇偶位），顺序扫描不再天然携带「我在不在紧贴」，它就必须被显式记住。

**「折磨」的来源**：一旦用手工沿前缀走位，就要自己维护 `pow10`、`pre`、后缀表下标 `f[len-i-2]`、末尾特判 —— 这些**全部**是第二条支柱缺失后长出来的赘生物。

## 计时与止损规则

「停手」和「换题」对那道题是同一件事，区别在**停手之后干什么**：训练里停手 = 看答案，比赛里停手 = 换赛道。比赛没有「看题解」这个选项。

| | 训练 | 比赛 |
|---|---|---|
| 阈值 | 思考 25 min | 40 min **无实质进展** |
| 停手后 | 看题解，写「卡在哪一条」 | 去做另一题，标记「可回来」 |
| 记录 | 思考用时 / 实现用时 **分开记** | 每题挂起时刻 + 当时排名 |

- **「无实质进展」不是「没做出来」**，而是：既没有 AC，也没有产生一个可验证的新思路。试了三种方向否掉两种 = 有进展，继续。
- **最快的换题时机往往是第一次 WA 之后**：WA 说明模型和题目对不上，而你没有修复它的证据。除非 WA 之后立刻看出哪条规则错了。
- 动手前必须能说清四条：**状态 / 转移 / 复杂度 / 边界**。任何一条说不清就别写，那不是「想到怎么做」，是「以为想到」。
- 1340B 的教训：25 min 时四条里第 1 条（状态里放了答案本身）和第 2 条（复杂度算不通）就已经不成立，但当时没停下来问。

**挂起后要不要回头**：回头必须由条件触发，不能由「不甘心」触发。挂起时记一行 `题号 / 已投入 / 当前结论 / 回来的条件`。

| 阶段 | 时间 | 原则 |
|---|---|---|
| 提速期 | 0:00 – 3:00 | 只开新题（例外：某题 5 min 内能 AC） |
| 收拾期 | 3:00 – 4:00 | 回头做「最接近 AC」的那道 |
| 封榜期 | 4:00 – 5:00 | 锁定一题死磕，不再分散 |

回头三条任一成立：① 说得出一处具体要改的地方；② 是所有未过题里最接近 AC 的（已有 WA 提交 / 主体已写出 / 只差边界）；③ 队友独立推出方向。
**沉没成本不是回头的理由。同一题最多回头一次**，第三次回去说明模型根本对不上。

**实测（真实数据 + 合成最坏数据，同机）：**

| 输入 | Floyd | 他写的 n 次堆 Dijkstra |
|---|---|---|
| 合成：500 线路、线路图全稠密 | **538 ms** | **17,367 ms** |
| subway6.in（n=480, m=4.8×10⁵, q=9×10⁴） | 262 ms | 236 ms |
| subway7.in（同上, d=2） | 381 ms | 345 ms |

输出**逐行完全相同**。稠密图上 **32 倍**，稀疏图上 Floyd 只慢 10%。

**根因不是复杂度，是常数**：稠密图下每次松弛都可能 `q.push`，`1.25×10⁸` 次堆操作（带 log + 扩容），而 Floyd 是同操作数的一次加法+一次比较，且 `k` 最外层时内存连续、全在 cache。

**判断信号**：**`n ≤ 500` + 全源最短路 → 先算 `n³`，那是 Floyd 的舒适区**，不要默认「n 次 Dijkstra」。除非图稀疏。\n\n**这类失误的定性**：不是不会 Dijkstra（他会，而且用得对），是**没把数据范围当信号读**。`n ≤ 500` 写在那里就是在说「`n³` 可以」。和 1512G 的「觉得会超时」是同一个病的两面：**一边不敢用贵的算法，一边没换掉常数大的算法 —— 都源于没有把规模换算成数字。**

**三个实现要点**：`k` 必须最外层；对角线先置 0（他的 `dir` 只更新 `u≠v`，对角线是 INF）；`if (dik == INF) continue`。
### 复杂度档位表（2026-11-01 收工前补，全部本机实测）

**「1e8 能不能过」是伪问题。同样 1e8 量级，实测差 190 倍。**

| 档位 | 操作 | 实测折算 | 1 秒上限 |
|---|---|---|---|
| ① 顺序、cache 友好（加/比/赋值/连续读写） | | **0.7 ns/次** | **1e9** |
| ② 有 `%` `/` 乘法（还有依赖链） | | **5 ns/次** | **1e8**（留余量） |
| ③ 跨步长 / 随机访问 40 MB 表 | | **8–11 ns/次** | **1e7 ~ 5e7** |
| ④ 堆 / map / set / 哈希插入 | | **~130 ns/次** | **1e6 ~ 1e7** |
| ⑤ 大对象搬运（vector 拷贝、string 拼接） | | — | **1e6** |

1. 循环是**顺序**的还是**跳**的？（跳 → 档位 ③，除以 20）
2. 循环里有没有**堆/树/哈希**？（有 → 档位 ④，除以 100）

**余量规则：估算 ≤ TL/3 才做。** TL/3 ~ TL 之间叫赌博，换算法。

**反推用法**：`n ≤ 500` → `n³` = 1.25e8 在档位 ①，**三重循环/Floyd 可以**；`n ≤ 2000` → `n³` 不行；`n ≤ 1e7` → 只能档位 ①。

C1 是 constructive（任意解），C2 是 checker（要最优）。**两版题面几乎逐字相同，只差这一句**，他沿用了 C1 的读法。

估账：若 C2 40 分钟过、0 WA，罚时 114 而非 194，rank 约 500 上下，Δ ≈ +20~30。**C2 的两次 WA 大约值 30 分 rating。**

**规则（新增）**：成对题（`A1/A2`、`C1/C2`）**必须并排写出两版差别**，并在 `// Time` 下写 3 行 `REQ:`（要求 / 范围 / 边界）。
CHECK 块查实现，查不到「题目要求」——所以要另一套东西。

## 归因二：D 是题型空白，不是失误

**D 是 run-twice（communication）题**：程序跑两次，第一次拿 $n$ 和串 $s$ 造图，中间对手对图做任意换边并打乱，第二次只拿图还原 $s$，**两次运行内存不保留**。CF 一年出现几次。
他的 D.cpp 是空壳（`for (int i = 0)` 停住）。

> **所以「D 只差 6 分钟」的说法是错的**，已收回。多给一小时也做不出来（本人判断，成立）。

## 他实际提交的 C2 解为什么对

### `wr` 拦下了一个反例：n = 2

他的第一版模型是：

```
ans[u] = f[u] + max(0, father's stream)
stream to son[x] = father's stream + f[u] - f[son[x]]
```

**`f[u]` 里加进去的是 `max(f[v], 0)`，减出来的却是 `f[v]`。加的和减的不是同一个数。**

最小反例就是一个二点树：

```
n = 2, a = 1 0, 边 1-2      ->  答案 `1 0`（点 2 只有 {-1} 和 {0}）

他的：f[2] = -1, f[1] = 1, stream[2] = 0 + 1 - (-1) = 2
      ans[2] = -1 + 2 = 1                    <- 错
改后：stream[2] = ans[1] - max(0, f[2]) = 1 - 0 = 1
      ans[2] = -1 + 1 = 0                    <- 对
```

改法顺带**删掉了一个变量**：`ans[u]` 算出来之后，`stream[x] = ans[u] - max(0, f[x])`，不再需要传 `father's stream`。**变量少一个，「加进去的」和「减出来的」就不容易再对不上。**

```
加 "-Wl,--stack=268435456" 编译：exit = 0，0.16 s
```

**处理**：
1. 本地编译统一加 `-Wl,--stack=268435456`（一行，永久有效）；
2. 更好的是**树的 DFS 一律写成迭代**：

```cpp
// 一次 BFS 求出父节点和访问序；第一遍逆序遍历，第二遍正序遍历
vi order; order.reserve(n); order.push_back(1);
for (size_t i = 0; i < order.size(); i++)
    for (int v : e[order[i]]) if (v != par[order[i]]) par[v] = order[i], order.push_back(v);
for (int i = n - 1; i >= 0; i--) { /* f，子树已经算完 */ }
for (int i = 0; i < n; i++)      { /* g，父节点已经算完 */ }
```

不依赖栈、比递归快，而且**第 5/6 题（DFS 序、子树区间）本来就必须拿到 `order`** —— 是同一套东西。

题目有一句「汽油不够的路不能走」（路径必须能从一个端点走通）。我写了**两个暴力**去对：一个按定义取 `Σw − Σc` 的最大值，一个要求路径真的能走通。

**他随后自己给出了理由（对的），补成可证明的版本**：

设路径 $v_1 \to \dots \to v_k$，边 $c_1,\dots,c_{k-1}$，总价值 $S$。记前缀价值 $A_i = \sum_{j\le i} w_{v_j} - \sum_{j\le i} c_j$。过第 $i$ 条边之前手里的油是

$$p_i = \sum_{j\le i} w_{v_j} - \sum_{j<i} c_j = A_i + c_i$$

所以

$$\text{卡在 } c_i \text{ 上} \iff p_i < c_i \iff A_i < 0$$

**不是整条路贡献为负，是某个前缀贡献为负。** 这时砍掉该前缀，剩下的 $v_{i+1}\to\dots\to v_k$ 价值是 $S - A_i > S$，**严格更大** —— 原路径不可能最优。从右端走不通时对称。

**结论：最优路径总从某一端能走通，这条约束在最优解上恒成立。**

> 通用动作：**题目里的一句限制，先问「它在最优解上生效吗」**。生效就为它设计算法；不生效就直接删掉。

他的写法是 `f[u]` 和 `g[u]` **一个变量担两种身份**：

```cpp

else if (add > g[u]) g[u] = add;

```

循环前 `f[u]` 是「最大臂」，循环后是「`a[u]` + 最大臂」。**同一个名字、两个意思、中间隔着一行赋值。** 这在改的时候非常容易错位。

```cpp

for (auto &[v, w] : e[u]) if (fa[v] == u) {
    ll add = f[v] - w;
    if (add > b1) b2 = b1, b1 = add;
    else if (add > b2) b2 = add;
}
f[u] = a[u] + b1;                                    // f[u] 从头到尾只有一个意思
ans = max(ans, f[u] + b2);
```

**Q3 最脆的地方：同一个函数里用了两套初始化约定。**

```cpp

```

**Q2 能更简单：两处。**

```cpp
col[v] = col[u] ^ w;                     // 染色
if ((col[u] ^ col[v]) != w) return -1;   // 冲突
```

```cpp
cnt[col[u]]++;
```

### 模型的四问全对

题面的「保护」定义是「$i \to j$ 且 $j \to i$」—— 就是**同一个 SCC**。所以每个 SCC 恰好要一个站、取最小费用，方案数是每块里「达到最小值」的点数之积。「最少站数」自动满足。

### 独立验证（这次的教训是我自己的）

`stress/427C_check.cpp` 第一版报了 3,999/4,000 全错 —— **是我的验证脚本错了**：427C 是单测，他的 `cnt` / `c` / `st` 是全局量**从不重置**，我在同一个进程里反复调 `Main`，`c` 一路累加，`p` 里全是 `INF`。

修法：每次调用前手动 `cnt = 0; c = 0; while(!st.empty()) st.pop();`，模拟新进程。

**（这条本身也是个真实隐患，见 Q3。）**

| 验收 | 规模 | 结果 |
|---|---|---|
| 随机有向图 $n \le 8$，费用取 $0..3$（制造大量并列最小值）| **4,000 组** | **0 错** |

| $n/2$ 个互不相交的二元环，$n = 10^5$ | 闭式：逐块 min 之和与并列数之积 | ✅ 18 ms |

### 三问

**Q1 形状：标准。** Tarjan 求 SCC，再对每个 SCC 求最小值和并列数。

**Q2 能更简单：`p` / `q` 两遍遍历可以合成一遍。**

```cpp
if (a[u] < p[col[u]]) p[col[u]] = a[u], q[col[u]] = 1;
else if (a[u] == p[col[u]]) q[col[u]]++;
```

一遍 `for (u = 1..n)` 就够，省掉第二次全量扫描和 `q` 的初始 0 判定。

**Q3 最脆的地方：`cnt` / `c` / `st` 是全局量，从不重置。**

```cpp
int n, cnt, c;
stack<int> st;
```

单测没问题。但这份 `dfs` 不是「无状态函数」—— 它依赖三个全局计数器的初始值。**这正是我自己验证时踩的坑**：连调两次 `Main`，第二次的 `col[]` 落在旧的 `c` 之后，`p` 数组长度不够、大部分是 `INF`。

**如果哪天题目变成多测（这题没有），这段代码会静默错。** 稳妥写法：把 `cnt` / `c` 作为参数传入，或在 `Main` 开头显式清零。

**另**：`dfs` 递归深度 $10^5$。CF 过了（栈 256 MB），本地要加 `-Wl,--stack=268435456`。

### 关于 `low[v]` vs `dfn[v]` —— 我用 13 万组数据推翻了自己的一句话

他问「为什么回溯边用 `dfn[v]` 不用 `low[v]`」。我原来的说法是「这是 Tarjan 最典型的错」。实测后：

| 场景 | `dfn[v]` | `low[v]` |
|---|---|---|
| **有向图求 SCC 划分**（13 万组随机图）| 0 错 | **0 错** |
| **无向图求割点**（10,500 组）| 0 错 | **31 组错** |
| 无向图求桥（10,500 组）| 0 错 | 0 错（本轮未测出差异）|

**所以「必须用 `dfn[v]`」在「只求 SCC 划分」这件事上不成立。** 原因：处理边 `u→v` 时恒有 $low[v] \le dfn[v]$，而 $low[v] < dfn[v]$ 意味着 $v$ 已能回到某个祖先 $w$，此时 $w$ 沿树边能到达 $v$，**二者本来就同属一个 SCC** —— 多压小的那些点不会把 $u$ 错误归并出去。

但**割点上 `low[v]` 是真错**，反例（$n=5$，边 `1-5, 2-4, 3-5, 4-5, 1-3, 2-5`，两个三角形共用点 5）：

- 正确：割点集合 = {5}
- 用 `low[v]`：`low[5]` 先被压成 1，回溯边 `2→5` 读到 `low[5]=1`，级联把 `low[4]` 也压成 1 → 判据 `low[4] >= dfn[5]` 不再成立 → **5 漏判**

结论：写 `dfn[v]`，理由不是「否则这题会 WA」，而是**它是定义、不依赖「`low[v]` 恰好等价」这条要额外论证的性质，而且在割点/桥那一侧是真 necessity**。

### 唯一的 bug 是一个字符

```cpp
if (v > 1 && !a[i][v - 1]) ...                         // 左：正确
if (v < n && !a[i][v + 1]) ...                         // 右：n 应该是 m
```

`n` 是**行数**，`v` 是**列**。所以只要列数 > 行数，右边那几列永远走不到。

**样例为什么没抓出来**：样例 1 是 `4×5`（$m > n$），但官方标注里第 5 列本来就不在可达区域 —— 这个 bug 恰好被掩盖了。

### 我自己也错了一次

我第一版的暴力脚本把「左移次数」上限定成 `cap = min(limL, m)`，理由是「不需要比列数更多的左移」。**这个理由是错的** —— 绕路时可以「左→右→左」，左移总数超过 $m$。

于是脚本报了两组「他的答案多 1」的假反例。改成 `cap = min(limL, n*m)` 之后，那两组消失，**32,400 组 9×9 密集墙全过**。

**教训（教练侧）**：构造暴力时，「状态上界」必须按最坏情况给，不能按直觉给。这次的直觉（左移 ≤ 列数）正是他代码里那个 bug 的镜像 —— 我们都把「列」和「行/列上限」搞混了。

### 关于 `queue` vs `deque`

他用的是普通 `queue`，不是 0-1 BFS 的双端队列。但：

| 验收 | 规模 | 结果 |
|---|---|---|
| 1..6 × 1..6 随机 | 10,800 组 | 只修 `v<n` 后 **0 错** |
| 9×9 密集墙，$x,y \le 8$ | 32,400 组 | **0 错** |

**FIFO 在这题的结构下是对的** —— 因为列内上下被整段压缩，0 代价的只剩「向右」，代价序与入队序没有分叉。

但这依赖题目的特殊结构。**换一道 0-1 BFS 就不成立**，所以盲打重做时应该写成 `deque`（0 代价 `push_front`、1 代价 `push_back`）。

> **测试网格必须同时覆盖 $n > m$ 和 $m > n$。**

这题的行/列边界写反了，而两组官方样例都是「宽 ≥ 高」，其中唯一能踩到的第 5 列又恰好不可达。

1. $1 \times 1$
2. $1 \times m$（只有一行）
3. $n \times 1$（只有一列）
4. **$n > m$** 和 **$m > n$** 各一组
5. 起点在四个角各一次

$w \le 10^6$、$n \le 10^5$ ⟹ 最短路最长 $10^{11}$，而 `int` 只到 $2.1\times10^9$。**必然截断，而且不报错**（走的是 `pair` 的转换构造，不是花括号窄化，只会 warning）。

正确：`priority_queue<pair<ll,int>>`。

> 我试图造一个「距离超过 $2^{31}$」的用例来实证这一点，但测试脚手架自己写复杂了（两次重编号），输出对不上，**结论只到「分析上必然截断」，没有干净的反例**。这条记下来，别当成已验证。

## L3-3 的 30 分是侥幸 —— 「AC 但错」又添一例

「最小面积三角形 ⟺ 极角相邻对」是**假命题**。反例：

```
6
5 5
0 0
1 0
-5 2
0 1
2 -5
```

真正的最小三角形是 $(0,0),(1,0),(0,1)$，面积 $0.5$；他的代码输出 $1.000$。三个顶点在各自角锥里都插了更远的点，互不相邻。

**它能 AC 是因为 `ans = S(a[0], a[1], a[2])` 兜住了，而反例里的三个点恰好是输入前三个 —— 打乱输入顺序即挂。**

$3000$ 组随机只有 $1$ 组失败 —— 「几乎总是对」的典型，但构造数据一秒能出来。

**正解方向**：$O(n^2\log n)$，旋转直线维护投影序（8 s 时限就是给它留的）。
