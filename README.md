# 训练与学业总控仓

**这不是一个纯代码仓库。** 目录名 `code` 只是历史遗留，本仓实际承载三件事：

| 目录 | 内容 | 维护者 |
|---|---|---|
| `OI/` | 竞赛代码（Codeforces / 洛谷 / 比赛 / 模板） | 主会话 |
| `plan/` | 计划、日志、规则、参考文档 —— **唯一真相源** | 多会话共写 |
| `stress/` | 对拍脚手架（不入库） | 主会话 |

## 会话划分

**原则：按「共享文件」划分工作区，按「注意力」划分会话。**
不要「一个工作区一个会话一件事」—— 跨领域决策（例如「11 月砍竞赛保高数」）需要同仓才能看见全局。

| 会话 | 负责 | 维护的文件 | 频率 |
|---|---|---|---|
| **主会话** | 竞赛训练 + 保研 + 全局调度 | `plan/progress.md`、`plan/baoyan.md`、`OI/**` | 每天 |
| 英语会话 | CET-4 | `plan/english.md` | 每天 |
| （可选）课业会话 | 绩点 / 期末 | `plan/courses.md` | 按需 |

## 跨会话协议：SNAPSHOT 区块

每个领域的 `plan/<领域>.md` **顶部必须有一个快照区块**，供其他会话低成本读取：

```markdown
<!-- SNAPSHOT:BEGIN —— 其他会话只读这一段 -->
- 最近一次模考：512（11-20）
- 每日投入：30 min
- 考试：2026-12-12
- 当前薄弱：听力 Section C
<!-- SNAPSHOT:END -->
```

**规则：**
1. 只有本领域的会话可以修改全文，其他会话**只读快照**。
2. 快照控制在 10 行以内，只放「别人做决策需要的数字」。
3. 主会话 `start` 时依次读各快照 → 得出当天三栏（课业 / 英语 / 竞赛）的安排。

## 硬规则

- **AC 的题按首次 AC 日期归档**到 `OI/codeforces/old/<年>/<月>/<日>/`，`.cph` 元数据一并修好（`organize.ps1 -Apply`）。
- **只按第一次 AC 记账**；后来的优化重交不计提交数。
- `tmp/`、`stress/` 不入库。
- 不往仓库里放个人证件的原始文件（PDF 等），只放提炼后的规则文档。
