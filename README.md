## 会话划分

**原则：按「共享文件」划分工作区，按「注意力」划分会话。**
不要「一个工作区一个会话一件事」—— 跨领域决策（例如「11 月砍竞赛保高数」）需要同仓才能看见全局。

| 会话 | 负责 | 维护的文件 | 频率 |
|---|---|---|---|
| **主会话** | 竞赛训练 + 保研 + 课业交付 + 英语调度 + 全局安排 | `plan/progress.md`、`plan/baoyan.md`、`plan/calendar.md`、`plan/courses.md`、`OI/**` | 每天 |

**英语不再单独开会话（2026-11-03 定）。** 原设计是「英语会话维护 `plan/english.md`，主会话只读快照」，但 `plan/english.md` **从未建立**，快照桥是空的 —— 两个会话真正的共享面是 `D:\study\English\CET4` 里的计划、打卡表、每日任务，主会话直接读这些文件比读一份转写快照更短，也不会出现「快照说 A、原文件说 B」。

### 上下文隔离：用 subagent，不用第二个会话

英语材料生产（从真题 PDF 抽阅读、按静音边界切听力音频、写任务单与批改）是**重工具、低决策**的活，会吃掉大量上下文，但不需要与竞赛共用推理。所以：

- **主会话只决定「今天练什么」** —— 一行：词块 10 个 / 阅读哪一篇 / 听力哪一段；
- **材料生产交给 subagent** —— 给它材料来源、答案键、输出路径，它写完只返回一句话；
- **打卡表与批改只有主会话写** —— 单一写者，避免两个会话改同一个 xlsx。

> 这条替代了旧的 SNAPSHOT 协议：同样做到「注意力隔离」，但少一层需要维护的中间文件。
